# テストコード作成の手順

## 全体フロー

```
[情報収集]
↓
[テストケース作成]
↓
[テストケースチェックリスト作成し、開発者に確認する]
├─開発者に過不足を指摘された場合、再度テストケース作成に戻る（了解を得るまでループする）
↓
[開発者の了解を得た場合、次のステップに進む]
↓
[前のステップで作成したテストケースをもとにテストコード作成]
↓
[テスト実行]
├─テストに失敗した場合は原因を調査したうえで開発者に報告し、フローを中断する
↓
[テストに成功した場合は成功した旨を報告し、フローを終了する]
```
## ステップ1：情報収集
詳細設計書（spec-detail出力）またはテスト仕様書（spec-test出力）をインプットとして、単体テストを用意する
充分な情報が得られない場合、ユーザーから以下の情報を収集する
- 正常系
- 異常系
- 境界値

## ステップ2：テストコード作成
最低限必要なテストケースは以下の三点
- 正常系
- 異常系
- 境界値

### 例外テスト
例えばArgumentNullExceptionを投げる場合は必ず作成
例：
```c#
[Fact]
public void NameがNullなら例外()
{
    Assert.Throws<ArgumentNullException>(
        () => service.Create(null!)
    );
}
```

### 条件分岐カバレッジ
条件分岐を見つけた場合は全分岐のテストを書く
例：
```c#
if(age >= 20)
```
なら19,20,21のケースを作成する

### xUnitの記述パターン固定
開発者の読みやすさを重視し、形式は統一する
// Arrange

// Act

// Assert
を強制
例：
```c#
[Fact]
public void 正常系()
{
    // Arrange

    // Act

    // Assert
}
```

### Theoryを優先
境界値はTheory化
```c#
[Theory]
[InlineData(0)]
[InlineData(1)]
[InlineData(2)]
[InlineData(99)]
[InlineData(100)]
[InlineData(101)]
public void 境界値テスト(int age)
{
}
```

### 作成前のチェックリスト
□ 正常系
□ 異常系
□ 境界値
□ null
□ 空文字
□ 空コレクション
□ 分岐網羅
□ 例外
□ 戻り値
□ 副作用
